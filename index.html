03 / THE WORKER NODES

Where the
work runs.

Each worker runs a kubelet to manage Pods and a container runtime to execute containers. Cluster networking connects them.

A Pod is the smallest deployable unit: one or more closely related containers that share networking and storage resources.

Service networking commonly uses kube-proxy or an alternative implementation.

04 / DEPLOYMENTS

Define once.
Run in replicas.

A Deployment declares the image, Pod template, and replica count. It manages ReplicaSets, which maintain the requested Pods.

Change the template to roll out a new version. Change the replica count to scale. If a Pod fails, a controller creates a replacement.

Recovery still needs available capacity. Autoscaling needs metrics and configuration.

04 / FROM THEORY TO TERMINALYOUR FIRST LOCAL DEPLOYMENT

Make it
real.

Create a local cluster. Deploy a web server. Give it an endpoint.

First install minikube, kubectl, and a supported container or VM driver.

  1. Start your cluster
  2. Create the workload
  3. Expose and inspect it
  4. Open the application
LOCAL / KUBECTL
# Start a local Kubernetes cluster
minikube start

# Deploy a web server
kubectl create deployment web \
  --image=nginx:stable

# Expose it inside the local environment
kubectl expose deployment web \
  --port=80 --type=NodePort

# Inspect and open
kubectl get pods,svc
minikube service web

06 / DISASTER RECOVERYASSUME SOMETHING WILL FAIL

Disaster recovery

Thingswill break.Design what happens next.

Disaster recovery restores service after a major disruption. Start with two targets.

How long can the application be unavailable? How much recent data can you afford to lose? Those answers shape the architecture.

07 / RECOVERY IN PRACTICETHE RUNBOOK MUST WORK

A plan you
can execute.

01 / PREPARE

Know what matters.

Map critical services and dependencies. Set RTO and RPO. Assign owners, contacts, and recovery priorities.

02 / PROTECT

Keep a way back.

Maintain recoverable backups, replicated data, infrastructure definitions, and clear runbooks.

03 / RESPOND

Restore with intent.

Detect the disruption, activate the plan, restore dependencies, and validate the application and its data.

04 / REHEARSE

Test before you need it.

Run recovery drills, measure results, improve the plan, and fail back safely when the primary is ready.

LOAD BALANCING & FAILOVER

Give traffic
a healthy destination.

Health checks and routing policies can shift traffic away from an unavailable site. The recovery environment must already have the capacity and data it needs.

A load balancer does not restore lost data. Cross-region recovery may also use DNS or global traffic management.
